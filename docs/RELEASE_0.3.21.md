# 0.3.21：按需观察、双角色与对话清理

## 呼出改为上浮切换，观察按需进行

呼出快捷键第一次把彩名置于上层，再按一次隐藏；打开聊天不再自动绑定窗口，也不持续截图，原来的 `Ctrl+Alt+W` 固定注视随之移除。

Agent 通过新的 `desktop.observe` 工具按需查看屏幕：`scope=list` 列出窗口，`foreground` 看前台窗口，`window` 看指定窗口，`desktop` 看整个桌面；桌面全景只作观察证据，操作前仍需选定窗口并取得新截图。开启「允许彩名偶尔偷看」后，她在显示且空闲时每 45–90 秒获得一次观察机会，同一窗口至少间隔约 3 分钟，相同画面跳过后续视觉请求；主动搭话至少间隔 5 分钟。隐藏、任务、语音播放或关闭屏幕观察时不会偷看。说「别看了」暂停，「继续看」恢复；明确要求看屏幕时仍可按需观察。

## 第二套角色

`characters/registry.json` 注册「彩名（黑制服）」与「彩名（白制服）」两套资源。切换只替换立绘与声音，人设、记忆和使用设置共用；表情目录、服装与对话中的表情动作随所选角色切换，设置写入各自的角色档案。导入方式见 README 的 `--su-avatar-root` / `--su-voice-root` / `--base-voice-root`。

## 对话删除

对话切换列表提供删除按钮。确认删除后立即清理该对话的消息、模型上下文、摘要、任务和关联记忆，会话独占的源与产物记录一并删除，随后回收 SQLite 数据页并截断 WAL；其他对话和已经导出的文件保留。新建文件现在会记录所属会话，便于随对话删除一并清理。

## 模型与工具健壮性

- 已提交并播放的语音不再被后续句子的修复失败连带中断：修复失败的尾句会被丢弃，已交付的 speech 保留。
- 模型把 `speech` / `translation` 误作原生函数调用返回时，按协议事件提交，而不是执行未知工具；未知工具报错会说明这两个是 NDJSON 事件、本轮只应调用提供的工具。
- 旧配置里残留的 `watch_hotkey` 会被清理，默认配置改用 `ambient_attention` 并加入角色注册表字段。
