# ayana_su 替换资源审查与接入设计

审查日期：2026-10-06。目标是替换现有 Ayana 的立绘与音色，沿用人设、会话和桌面能力。本文为接入设计，尚未切换应用默认资源或修改运行配置。

## 结论

新立绘可接入，但不能只修改 `avatar_root`。需要一起调整素材导入、表情路由、姿势协议、前端目录和缩放。建议默认使用正面双手交叠，侧身用于有语境依据的姿势变化；同一姿势中逐句更换表情。背身和模糊背影不进入普通对话表情池。

语音可复用原来的 Python 与 GPT-SoVITS 引擎。新权重已通过项目现有 TTS 接口加载并预热，但正常句子的合成出现长度上限错误，尚不能据此认定语音可直接交付替换。

## 显示比例

当前 CSS 的立绘高度为 `min(1193px, 200cqh - 156px)`，是为 1656px 高的旧全身图取上半身设计的。以立绘容器高 500px 为例，图片高 844px：旧正面宽约 241px，新正面会宽约 582px，头部显著放大，左右也可能裁切。

新包应有自己的显示参数，而非继续共用这个高度公式。建议：

- 保留完整源 PNG，在显示时调整比例与位置，由不透明对话框遮住下部。
- 正面与侧身使用相同缩放比例，按头顶及脸部位置校准各自的水平锚点，避免转姿势时头部跳动。
- 在 440px 宽、500px 高的示意容器内，以图片高约 570px 作为第一次试排值；此时正面宽约 393px，侧身宽约 396px。它是试排起点，最终按实际窗口验证。
- 容器变窄时同时限制宽度；对话框变高时限制缩放和裁切，确保头、肩和主要躯干仍可见。
- 保留当前对话框遮挡和呼出动画。无需对源图添加渐隐，亦无需重编码源文件。

验收必须包括实际 680×760 窗口、较窄窗口、长字幕和不同 Windows DPI。

## 表情与姿势切换

### 默认与时机

初始立绘建议 `ay0000a`（正面平静），轻松问候可用 `ay0001a`（正面自然微笑）。这延续当前交叠姿势的陪伴感。

保留现有时序：`utterance.ready` 预加载资源，有语音时在 `playback.started` 切换；文字模式在 `desktop.present` 切换。模型生成下一句或正在合成时，保持已展示的立绘。

正面／侧身不是说话／停顿状态。默认保持当前姿势，只有语境确有变化时才请求切换，例如从倾听转向解释、从认真转向轻松调侃。可以保留姿势切换冷却，但取消旧代码对「摊手」的 12% 随机放行；不能直接把它套到侧身。

同姿势换脸可复用用户已经选择的 12px／300ms 下沉效果及关闭选项。姿势切换建议试用约 120–180ms 的淡出再淡入，避免两套身体长时间叠成双影；相同图片不重复动画。新图加载失败时保持旧图，并记录失败。尊重减少动态效果设置。

背身 `ay0000b` 可以以后用于明确退场；`ay0300` 可以用于专门的远景场景。当前隐藏面板已有收起流程，首版不必为了消耗这两张素材新增动作。

### 表情目录

不能沿用旧的 26 个表情名来要求新图表现不存在的脸。新目录应按实际标定建立语义说明：

| 编号族 | 标定内容 | 对话用途建议 |
| --- | --- | --- |
| 0000 / 0100 | 平静／脸红平静 | 陪伴、倾听、认真解释；脸红需要羞涩依据 |
| 0001 / 0101 | 自然微笑／脸红自然微笑 | 问候、安慰、温柔回应 |
| 0002 / 0102 | 得意，闭嘴笑 | 自信、展示完成的结果 |
| 0003 / 0103 | 得意，微张笑嘴 | 更活跃的得意、轻松调侃 |
| 0004 / 0104 | 正面不满；侧身闭眼嘟嘴 | 轻微抱怨、闹小别扭，保留眼睛差别 |
| 0005 | 病娇 | 明确受邀的角色互动 |
| 0105 | 病娇惊讶，脸红 | 独立强烈表情；不能作为普通吃惊的兜底 |
| 0006 / 0106 | 担忧／脸红担忧 | 关心、温和提醒 |
| 0007 / 0107 | 委屈／脸红委屈 | 自己受委屈、难为情；不等同于哭泣 |
| 0008 / 0108 | 疑惑／脸红疑惑 | 不理解、确认、好奇 |
| 0009 / 0109 | 吃惊／脸红吃惊 | 意外、惊讶 |
| 0010 / 0110 | 无奈／脸红无奈 | 苦笑、尴尬、温和吐槽 |
| 0011 | 坏笑 | 俏皮、调侃 |
| 0012a | 眯眼坏笑，仅正面 | 更明显的戏谑，侧身无对应图 |

`a` 后缀为正面，无后缀为侧身。没有侧身 `0012`，也没有 `0111`、`0112`，不能按编号自动拼接路径或假设所有组合齐全。

导入目录应保留原编号、情绪、眼睛、嘴型、脸红和视角。面向模型可使用明确的完整标签区分「得意」与「得意开口」、「坏笑」与「眯眼坏笑」；否则同姿势的重复标签会被当前路由的首个匹配吞掉。正面「不满」与侧身「闭眼嘟嘴」也应有各自的描述与可用组合。

普通开心优先自然微笑，`surprised` 可兜底到吃惊，解释可兜底到平静，安慰可兜底到自然微笑，提醒可兜底到担忧。缺少旧图的愤怒、哭、掩饰等，不制造同名新素材，也不继续让新模型输出这些旧标签。强烈表情和脸红仍需要台词依据。

嘴型标注描述的是静态图状态。这批素材没有足够的统一嘴型／眨眼帧，首版继续逐句表情切换；不把开口图绑到每个音频采样来假装口型同步。

## 必须修改的接入点

| 文件／层 | 当前限制 | 推荐调整 |

| `services/agent/avatars.py` | 固定目录；仅筛选 `aya_` ID；默认 crossed；兜底为旧标签 | 按当前资源包载入目录；使用 front／side 及新表情；明确处理缺失组合 |

| renderer 的 styles | 针对全身素材的高度公式 | 新包单独的缩放、位置和姿势锚点 |
| `scripts/package_backend.py` | 固定打包 assets/ayana、旧映射 | 打包当前目录实际引用的资源；前后端目录必须一致 |
| Python／桌面测试 | 固定 234 张、26 表情及旧服装 | 保留旧包回归，增加新包缺失组合、初始化与切换验证 |

建议给资源包一个 `profile_id=ayana_su`，其下关联立绘映射、表情说明、显示参数和语音配置；这不会创建第二套人格。沿用 `characters/ayana/persona.md` 和现有历史。

素材 ID 建议采用 `aya_su__ay0000a` 这样的完整前缀：既兼容当前 `aya_` 筛选和 Electron 资源地址字符规则，也与旧素材不冲突。建议独立保存新资源，保留旧包用于回退；只将默认配置指向新包。首版无需增加复杂的角色管理界面。

切换时应取消旧句和排队音频，更新整组资源并预加载默认脸；语音 worker 按新配置重建参考缓存。最近表情上下文应按资源包过滤，旧立绘记录继续可读但不作为新脸的延续依据。

用户原来保存的服装可能在新包中不存在。加载新默认资源时必须同时迁移为白色短袖校服，否则路由会走错误服装兜底。发布包还需检查 `%APPDATA%/Ayana/config/local.json`，只改开发目录的配置不会更新已有用户配置。

第二轮结果：

| 测试文本 | 结果 |
| --- | --- |
| ここにいるよ。 | 合成约 22.4 秒后，触发完整句尾生成前的长度上限 |
| まず、原因を一緒に確かめよう。 | 合成约 24.1 秒后，同样触发长度上限 |
| こんにちは。ここにいるよ。 | 两块音频返回成功，但总时长 48.74 秒，短台词异常延长；合成约 34.3 秒 |

两次相同输入出现不同结果，说明还存在随机性。只有三个复测样本，不能推算整体错误率。未试听或使用 ASR 核对这段异常长音频，不据时长推断其中具体说了什么。记录见 `.runtime/reviews/ayana-su/voice-smoke-first.json`、`voice-smoke.json`；成功返回的音频保存为 `voice-3.wav`。

新包自己的辅助脚本存在短输入超长后裁剪逻辑；它与项目当前要求完整句尾的推理路径不同，因此包内有样例音频不能代替应用接口验证。当前证据只能确定加载可用和合成存在兼容性风险，不能将原因直接归到参考音频、权重或句尾保护中的某一项。应在实际替换语音前诊断并验证正常短句、长句句尾及打断恢复。

## 验证与实施顺序

本次已有检查：49 张素材读取、透明与哈希检查；47 张正向表情联系表；显示比例静态试排；现有 avatars、expression_context、costume_change、protocol 四组测试共 25 项通过；新音色真实加载与合成检查。

建议实施顺序：先接新目录与默认正面，修正显示比例；再接 front／side 路由、新表情说明和姿势动画；处理现有配置迁移与前后端目录一致性；语音合成问题修复并回归后，最后联动新音色并打包。

替换完成的验收包括：新默认脸与服装恢复、每个可用组合可达、缺失图不黑屏、取消后不展示排队句、资源包切换不串音色／旧脸、窄窗口与长字幕不裁掉脸、语音句尾完整，以及实际发布包运行。当前审查不宣称这些尚未实施的项目已经通过。
