# 设置整理与项目审查 · 2026-10-06

## 本次结果

设置使用单层侧栏，分为「偏好设置」和「管理」。常用偏好为外观与声音、模型与连接、权限与隐私；任务与结果、对话记录独立。高级设置置于侧栏底部，快捷键、预算、兼容/代理与诊断默认折叠。保留项目现有 KunUI 视觉风格，移除仓库界面、第二层导航、设置搜索、重复说明和空结果卡片。

| 原有问题 | 本次处理 |
| --- | --- |
| 模型、服装、快捷键、隐私混排，两层导航与设置搜索增加选择负担 | 单层导航，常用三分类，低频高级参数折叠，固定保存区 |
| 任务页混放权限、目录授权、运行进度和操作结果 | 权限与目录授权集中到权限页；任务页优先显示进度、待确认操作和实际结果 |
| 仓库入口、文件证据侧栏和多处说明挤占设置空间 | 移除整个仓库界面和第三栏；窗口操作在任务页按需展开；对话记录省去空上下文和重复说明 |
| 修改一项时提交整张表单，并附带语音配置 | 只提交变更字段，嵌套配置只提交变更的叶子字段 |
| IPC 接受发送就显示“已提交”，后端保存失败无法正确反馈 | 使用 request_id 匹配后端保存回执；成功写入才显示保存成功；失败和超时保留草稿 |
| 切换页面或接收 settings.ready 时表单重新挂载 | 表单保持挂载；刷新只合并未编辑字段，保留本人的草稿 |
| STT 局部修改覆盖已有模型、路径或提供方 | 后端合并 STT 配置，增加重载保留测试 |
| 文件写入失败后，内存已被更新 | 先写临时文件并替换成功，再更新内存 |
| 无效配置先取消正在进行的任务 | 先校验再取消；错误输入不影响当前 generation |
| 设置错误既出现在表单，又出现在全局横幅，并把任务状态改为失败 | 带 request_id 的错误交给发起操作的表单处理 |
| public() 将 model_max_tokens 误当成敏感 token 字段隐藏 | 放行该已知整数预算；保持嵌套凭据过滤，并验证保存/刷新后的可见性 |
| 快捷键提示写死 | 提示读取实际配置；空值和相同快捷键被拒绝，注册失败显示反馈 |

主要实现：[SettingsPanel.tsx](../apps/desktop/renderer/SettingsPanel.tsx)、[preferences.ts](../apps/desktop/renderer/preferences.ts)、[config.py](../services/agent/config.py)。设置默认值直接来自项目的 `config/default.json`。

## 已扩充的功能

- 语音识别语言：自动、中文、日语、英语；保留已有自定义语言及本地模型路径。
- 回复预算：普通/详细回复的句数上限、在线模型单次输出 token 上限。
- 高级设置：折叠原生工具调用、回复/任务限制、本机代理、快捷键和服务诊断。
- 搜索配置：自动/Bing/Brave，折叠的 Brave 本机 HTTP 代理选项。
- 单任务预算：处理轮数、工具调用次数、最长时间；沿用后端真实限制。
- 服务诊断：本地连接、语音引擎、模型凭据、桌面执行能力；可刷新状态和重启。
- 保存体验：未保存状态、撤销修改、保存中的防重复提交、失败保留草稿；Full access 与普通设置统一提交并等待保存回执。

这些功能均接通现有后端。服务诊断的“已配置”不等同于远程接口连通性测试；改变任务预算作用于后续任务。保存设置会停止当前任务与语音，更换声音引擎会自动重新加载。关闭历史保存不会删除已有记录，切换会重新建立话题和清除材料绑定，界面已说明。

## 项目审查与建议

审查基于当前工作区的 Ayana 自有代码：React/Electron、配置与会话、模型/工具协调、历史存储、TTS/STT 进程接口、Windows 截图边界、构建与测试。外部 GPT-SoVITS/Whisper 引擎未作完整源码审计，本次也未重新评估实际音色听感。

现有模块化单体加独立语音进程适合单用户 Windows 桌面同伴。保留透明对话窗口、独立管理窗口、真实工具回执和受控 IPC 的边界。当前没有证据支持增加远程微服务。

较早审查里提到的 WebSocket 广播队列、SQLite 调用移出事件循环、快照总内存预算和截图缩放，现在均已实现，不应再次当成未完成事项。工具元数据与访问描述也已有统一注册表。本次建议聚焦仍存在的缺口。

| 顺序 | 当前代码依据与影响 | 建议与验收标准 |
| --- | --- | --- |
| 1 · 长期容量 | `services/agent/storage.py:47` 保存 events/utterances，没有时间或总容量清理；capability_records 已限制部分记录数量。`conversations.py:90` 的 live 记录仅在持久化开启时限制为 200 条，临时话题可持续增长；前端 questions 也仅追加。TTS 的 `_cancelled` 和 worker 的 tokens 长期保留。 | 建立历史保留策略、临时会话/录音回执容量上限、话题导出/删除入口；清理语音 token 前必须确保相关推理和队列已结束。用长时间、多话题、频繁取消测试确认内存和数据库增长受控，迟到回执不串话题。 |
| 2 · 配置契约与恢复 | `services/agent/config.py:22` 对本地 JSON 使用浅层覆盖，加载阶段不经过更新校验；voice/stt 仍允许任意嵌套字段。坏类型或损坏文件可能影响启动，而设置页需要服务就绪才能编辑。 | 引入完整配置 schema、默认值合并和版本迁移，提供保留原文件的恢复入口；将 renderer 的宽泛 RuntimeEvent 与 Electron 命令白名单逐步对齐共享契约。验收覆盖旧配置、缺字段、损坏 JSON、错误类型、嵌套凭据隐藏和升级回退。 |
| 3 · 首次使用 | 语音资源路径和模型/Brave 凭据仍主要依赖配置文件、环境变量与脚本；高级诊断能解释状态，但不能完成全套设置。 | 增加首次配置引导：资源选择与检查、本机安全凭据录入、用户主动触发的模型连接测试、语音试听、快捷键录制。凭据只在本机受保护保存，测试失败保留输入并给出可行动原因。 |
| 4 · 交互延迟 | `runtime.py:104` 已用后台线程写库及有界广播队列，但 emit 仍等待每次持久化后再广播，`storage.py:71` 每次 commit。慢磁盘可拉长首句和回执发布延迟。 | 先测量模型首字、首句、合成、真实播放、取消和持久化耗时，再考虑单写入者和批量提交；保留关键最终回执的耐久性。用慢磁盘模拟验证顺序与恢复，优化不能破坏取消和播放核验。 |
| 5 · 发布可复现性 | Python 依赖为范围声明；`scripts/package_backend.py:110` 直接复制开发 .venv/site-packages。现有 manifest 和 hash 有帮助，但不能固定构建输入。 | 固定经过验证的 Python/语音引擎依赖清单，用干净构建环境打包，并记录源码、依赖和资源版本。不同机器从相同输入构建后应通过相同协议、设置迁移和启动验证。 |

产品功能优先级建议：先做配置引导与语音试听，再做话题导出/保留策略，之后补任务结果筛选、失败原因和状态诊断导出。当前已有任务暂停/取消、文件恢复和完成核验，继续扩充应围绕这些能力提高可见性和可恢复性。
