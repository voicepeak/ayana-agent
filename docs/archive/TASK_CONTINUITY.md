# 通用任务理解与完成核实

彩名的语气由人设控制，当前用户目标、实际权限和工具证据决定行动。具体问题先回答；操作持续推进；长解释按请求深度分句播放。任务机制不按某个故事、文件名或应用名匹配用户句子。

## 每轮任务报告

模型在 NDJSON 中输出 `task` 事件，区分 `chat`、`answer`、`action`，记录解析后的目标、回答详略以及操作任务的全部完成条件。模型继续使用原有 NDJSON 或原生 function calling 调用工具。

操作完成报告必须引用**当前任务中已执行工具的 call_id**，通过相对于真实 `result` 的 JSON pointer 和 `equals`/`contains` 比较核实各项条件。未知调用、不存在字段、失败命令、超时、只发送输入或打开请求的回执不能支持完成。不能删掉最初的条件来宣称复合任务完成；已有目标可以通过新的读取证据核实，不必重复写入。

未核实且仍有轮次预算的操作会得到一次具体的修正反馈，要求继续未完成的步骤或核实已有结果，避免重放成功操作。无法继续时使用 `blocked` 或 `needs_input` 并说明具体原因。没有任务元数据的旧式纯语音回复标为 `replied`；旧式操作没有完整完成证据时标为 `needs_verification`。

这是一层证据一致性检查。条件是否完整覆盖用户意图、引用的事实是否足以证明复杂语义目标，仍依赖模型理解；例如一个窗口出现不能自动证明窗口里的全部操作正确。该机制不会声称能机械证明任意自然语言目标，也不替代既有工具授权与用户确认。

## 话题中的任务对象

`conversation.work_context` 保存最近任务、最多 8 项尚未完成的操作、最多 16 个工具返回的对象引用，以及最近工具错误。引用可包括文件、应用、来源、网址和窗口；不保留文件正文、脚本、截图或音频。文件被后续读取和打开时仍保留创建归属。接续报告通过本话题真实的 `continues_task_id` 关联旧任务，完成其他任务不会清掉原来的未完成事项。

上下文压缩不移除这些引用。持久化开启时支持重启恢复；关闭时只存在当前内存话题。已有话题第一次使用时，会从该话题近期真实工具事件恢复引用，不读取其他话题。引用是历史证据，实际是否存在、可访问、仍为同一窗口，必须通过当前工具核实；它们不能授予权限或自动重放旧任务。

每轮还传入本地时钟、当前访问模式、授权目录、普通和详细回答的语音额度。`detailed_max_utterances` 默认 32，可配置 12–64；每句仍接受现有日语完整句和长度校验。截图用于观察，不能替换用户指定的任务对象。

## 指定应用打开文档

`files.open` 可接收 `apps.search` 返回的 `app_id`，将经过路径授权检查的真实文件交给受支持的文档应用。已有适配覆盖 Code、记事本、Notepad++、WordPad、Office、LibreOffice、Acrobat、SumatraPDF 和画图。适配是应用的文件参数约定，不是用户任务的关键词路由。

快捷方式由程序解析，文件路径作为独立参数传递；模型不能注入启动参数。未知应用或带额外参数的特殊入口会返回明确原因，可使用已有绑定窗口和桌面工具继续。`open_requested` 只表示 Windows 接受请求；仍需观察指定应用中的目标文件。

## 验证

`tests/test_work.py` 覆盖复合条件、假调用和失败回执、未完成后的继续执行、防重复写入、详细回答、话题隔离、压缩与重启、旧记录迁移、不同文档应用及快捷方式参数。

本机真实模型测试在临时目录验证时间问答、详细算法解释、创建并读取清单、用短指代接续修改和普通模式的确认后继续。测试结果保存在忽略提交的 `.runtime/benchmarks/work-live.json`；测试不会改动用户原有笔记。
