# 工具接口整理

日期：2026-10-05。本次修改源码，分三个步骤提交。

## 1. 统一读取和列举

模型工具从 20 个整理为 18 个。移除模型入口 `read_file` 和 `list_files`，统一使用 `files.read` 和 `files.list`。

- `files.read` 支持完整读取和 `start_line`/`max_lines` 分段读取。完整 UTF-8 文件保留内容哈希；超出读取预算或替换解码的片段不提供可用于修改的哈希。完整覆盖文件的读取保留原始换行。
- `files.list` 支持当前目录、递归以及仅列文本。遍历上限为 3 秒、5000 条目录项、12 层深度，并报告截断。
- `root_id=repository` 表示当前所选仓库，只读、随话题材料切换；不写入普通目录授权记录。用户目录和默认产出目录仍使用实际授权 ID。
- 读取、列举、名称搜索和内容搜索省略 `root_id` 时，优先当前仓库，否则使用 `output`。修改和启动工具仍要求明确目标。
- 仓库管理界面的读取/搜索命令保留，内部适配到共享的文件读取与目录检查，不再维护另一套私有路径规则。

## 2. 区分搜索用途，共用实现

`files.find` 按名称找文件或目录；`files.search` 按文本内容返回路径、行号和原文。旧模型入口 `search_text` 移除。

两者使用同一授权范围和目录遍历器，统一排除私有文件、生成目录、符号链接和 Windows 重解析点。内容搜索最多检查 400 个文本文件，每文件读取 64 KiB；截断不表示已穷尽结果。共享规则还支持 Dockerfile、Makefile、LICENSE 等无扩展名源码。

## 3. 按实际条件提供工具

- 没有搜索凭据：不提供 `web.search`；用户给出网址时仍可使用 `web.fetch`。
- 没有目标窗口：不提供 `capture_target`、`observe_controls` 和 `computer.run`；Windows 窗口发现入口仍可用于选择目标。
- 截图关闭：不提供 `capture_target`；桌面执行还受组件、模型及截图配置约束。
- 教学模式：隐藏实际写入、打开和窗口选择工具；文件修改预览保留。执行器继续独立校验模式、目录授权、任务状态和确认，隐藏工具不代替权限检查。
- 没有实际备份或对应目录不能写入：不提供 `files.propose_restore`。

工具清单在每次模型往返和确认后续接时刷新。因此执行模式下可以先启动应用、选择窗口，再在下一轮获得观察和桌面操作工具。

原生调用使用 API 的函数 schema，不在系统提示中重复整份参数定义。NDJSON 模式继续提供完整定义，并在原系统消息内更新，不把每轮工具清单写进历史。模型在 NDJSON 中使用本轮函数 API 名称时，通过本轮显式名称映射转换；未知名称不会被猜测或自动授权。
