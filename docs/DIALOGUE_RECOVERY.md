# 对话异常修复（2026-10-05）

检查本机 `%APPDATA%/Ayana/.runtime/history.sqlite3` 中的对话事件，发现三次 `speech_ja must contain Japanese speech` 和一次 `Model application events were incomplete or malformed`。当前数据库 `quick_check` 返回 `ok`；系统语音未安装、旧 worker 退出和数据库损坏属于更早的记录，近期未出现语音合成失败。

## 行为

- 模型适配器在事件交给对话及语音队列之前检查日语句子。第一条事件尚未输出时，日语或协议校验失败会附带明确约束重试一次。
- 已经输出事件后，不重放模型轮次。后续不合格句子通过一个不带工具、限时 20 秒的请求单独改写，保留句子 key 和表情等元数据。结果再次通过句子校验才允许进入语音队列。
- 只有明确为最后一句日语的损坏末尾字幕才可自动补回；根据已确认日语重新翻译，不执行坏 JSON 中的内容。其他坏事件仍报错。
- 修复后的完整事件写入模型上下文，避免下一轮模仿坏句或坏字幕。普通回复继续保留原始格式。
- 后续事件报错时，已确认的语音仍可完成合成。打断或开始新一轮依然立即取消；worker 提前退出时不会堵住结束队列。
- 原生工具参数不是有效 JSON 对象时直接拒绝，不再将坏参数替换成空对象。

日语检测仍是协议层的文字与句尾检查，不能证明每个句子的语义或语言纯度。自动修复依赖配置的模型服务；修复请求失败或结果不合格仍会报错，并保留已确认语句。

## 验证

后端回归：239 通过、7 跳过。桌面测试与 TypeScript 构建通过。回归覆盖首句中文/英文/不完整句子、后续坏句、末尾坏字幕、修复失败、坏工具参数以及语音 worker 提前退出。
