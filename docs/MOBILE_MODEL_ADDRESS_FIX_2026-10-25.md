# 手机回复中断：纯汉字称呼误判

## 现象与原因

手机显示仍连接，但回复报 `invalid_model_repair`。实际记录中，模型先输出一条独立的纯汉字昵称，再输出正常日语与中文翻译。协议校验原先要求每条日语都至少包含一个假名，导致昵称在首句就被拒绝；格式修复通常会保留昵称的汉字写法，因此仍失败，连带后面的正常回复无法提交。

## 最终修改

仅修改 `packages/protocol/events.py` 的语言判定：允许 1–12 个汉字或迭代符号组成、带句末标点的短称呼。保留 48 字限制、完整句限制、代码／链接／路径限制及其余语音校验。原始称呼保留，不编造读音，不删掉后续回复，也不增加模型重试次数。

字符规则只判断文字形式，不构成语义上的语言识别；日语表达仍由现有人设和输出协议约束。

## 验证与应用

- 对协议、模型格式容错、独立手机网关及运行时执行回归检查：98 项通过。
- 将测试账号最近 9 份失败回复只读取出，在独立本地进程重新解析；9/9 均得到完整日语和中文事件，无需格式修复调用。未把这些内容重发给模型或测试会话。
- 本地统计报告：`.runtime/benchmarks/mobile-model-address-repair/report.json`。
- 生产网关进程不会自动加载此 Python 修改，需要重启网关才生效。远端测试期间尚未执行重启；应先协调测试者暂停，再应用并验证连接恢复。
