# Ayana 聊天提示词调研与口癖检查

调研日期：2026-10-16。范围是有官方文档或公开源码、与聊天或角色陪伴相关的产品和项目。这里不做聊天质量排名，也不把角色配置文档当作产品完整内部系统提示词。

## 当前实际运行状态

检查时，本机运行的是 Ayana 0.3.23 便携版，后端位于临时解包目录。其人设、说话规则、表情规则和提示组装代码都与工作区版本不同：运行包仍保留 10～24 字的倾向，以及为了尝试新表情而调整措辞的指令。

因此，工作区修改并未更新当前运行包。仅重启旧 EXE 也会继续解包旧提示词；需要重新打包，或使用开发版。此次没有覆盖运行包或改写会话历史。

源码和安装配置的模型均为 deepseek-flash，temperature 为 1.0。本文不将换模型或改采样参数的效果混入提示词对照。

## 历史里是否有口癖

只读检查了活动历史库中最近 180 句已显示的日语回复，涉及 42 个回复轮次；窗口边缘的轮次可能不完整。未使用备份历史库作为统计样本，真实历史没有送入本次联网评测。

| 检查项 | 观察值 |
| --- | ---: |
| 带省略号的句子 | 34 / 180 |
| 带省略号的回复轮次 | 26 / 42 |
| 出现用户姓名的回复轮次 | 18 / 42 |
| 末尾为问号的回复轮次 | 15 / 42 |
| 出现「哀れ」的轮次 | 0 / 42 |
| 出现「ふふ」的轮次 | 0 / 42 |
| 出现「ここにいる」的轮次 | 2 / 42 |

这些是描述统计，不是自然度评分。问候的合理重复、用户主动要求的复述、正常日语句尾都不能直接判为口癖。

人工阅读后，更值得注意的是结构惯性：先摘出用户的关键词，接一句感叹或抽象评论，然后反问、叫名字或补一句意味深长的收尾。部分日常分享也被引到较大的哲学结论。它们不一定重复同一串字，但会产生相似的听感。

另外，PromptHistory 会保留历史助手回复，系统提示更新后也不会清空当前对话。由此推断，旧回复仍可能成为后续语言风格的示范；本次未单独证明它对口癖的因果贡献。评估新版时使用新对话有助于减少这一干扰，无需删除原来的历史。

## 连续对话评测

用同一模型与 temperature，对上一轮修改版和本次精简候选版进行对照。每版包含两组各六轮的连续对话，以及四个独立问题，共 16 轮。覆盖日常分享、短回应、调侃、明确表达偏好、换话题、文学讨论和意见不同。

两版使用相同的 NDJSON、语音上限、表情目录、合成运行上下文和语音修复逻辑；候选版仅替换人设与说话规则。没有调用观察或搜索工具，没有写入用户会话或播放语音。这里的比较对象是上一轮源码版，不是正在运行的旧 EXE。

| 检查项 | 上一轮修改版 | 本次候选版 |
| --- | ---: | ---: |
| 成功生成的回复 | 15 / 16 | 16 / 16 |
| 成功回复中的句子数 | 40 | 36 |
| 以问号结束的成功回复 | 8 / 15 | 4 / 16 |
| 使用用户姓名的成功回复 | 1 / 15 | 0 / 16 |
| 带省略号的成功回复 | 0 / 15 | 0 / 16 |
| 相同五字符开头出现至少两次 | 未发现 | 未发现 |
| 不跨句的相同九字符片段出现在至少三轮 | 未发现 | 未发现 |

这是小样本、单次随机采样，不足以证明长期没有口癖，也不能把追问更少直接等同于聊天质量更高。

候选版较容易在内容说完时停下，也保留了文学问题上的展开。但两版都出现过：用户略过一个问题后，继续把它当作有意隐瞒来打趣。候选版仍有抽象化措辞和不必要推测，不能宣称已经完全自然。

评测还暴露了多句问候被装进同一条语音后的修复问题。本次把修复提示明确为“多句即使总长度未超限，也要分别返回”，并用真实修复请求核对拆分。最终对照中上一轮修改版仍有一次问候修复失败，已计入失败数，没有删掉该样本；提示词无法保证模型每次都遵守格式。

本机原始合成样本、指标和被测系统提示保存在 `.runtime/prompt-research/`，不纳入 Git。其中 `dialogue-audit.json` 是本表对应结果，`current.system.md` 和 `candidate.system.md` 是被测快照。

## 本次采用的调整

1. 人设集中描述身份、兴趣、好恶与相处分寸，移除单独展示的标志性口头短语。人设从上一轮的约 1300 字符缩到约 580 字符。
2. 接话方式、称呼、长短和连贯性归入 speech-style；协议、权限和表情继续由各自的模块负责。Ayana 已有分层机制，无需为此重写运行架构。
3. 对最近的回应结构保持敏感，不给每轮都补称呼、反问或感叹；保留有内容时主动展开的空间。
4. 表情继续按对白选择，不用表情覆盖率决定说什么。48 字保持为单事件技术上限，不恢复固定短句目标。
5. 本次对话样例用于验收，不固定注入生产提示词，不增加逐轮禁词表、随机口头禅或句尾配额。

不全局禁止「ね」「よ」等正常日语表达；口癖检查应结合它出现的语境、位置和回应功能。后续最有价值的检查，是在新版实际使用一段时间后，观察同类结构是否跨话题持续出现，而不是继续堆“不要重复”的文字。

相关提示组装、模型适配、角色、表情上下文和心情模块的 76 项测试通过。它们验证协议和运行兼容性，不替代实际聊天的主观评价。

## 0.3.24 落地记录（2026-10-17）

已将这轮人设、语言与两套表情规则纳入 0.3.24，并补充对“对方略过问题或换话题”的处理：接受当前给出的信息量，继续回应最新内容，避免把简短回应都解释为隐瞒或冷落。

新增 `scripts/check_dialogue_style.py`，可以只检查场景和提示词指纹，也可以使用配置的在线模型运行合成对话，或与一个旧系统提示词快照对照。逐轮日中对白、失败、重复开头、称呼、问句结尾与省略号等指标保存到新的 JSON 报告；失败不会被悄悄当作有效回复统计。它不读取真实用户历史，不执行工具或播放语音。

语音适配也作了修正。模型将几句合并进同一条 speech 时，如果原文可以按现有句界拆开，且拆开的每句均满足协议，就保留日语原文和语气，只请求对应字幕；对返回的句数和日语原文逐一校验。超长或无效的单句仍走已有的受限改写。新增回归覆盖短问候、引号内问号、元数据与字幕对应、原文被改写或句子被重新合并的拒收。

最终源码版另跑了 16 轮合成对话：16 轮成功、共 41 句，3 轮以问号结尾，没有主动使用用户姓名或省略号，没有发现重复的五字符开头或跨至少三轮的九字符片段。它能对短回应只说一句，也能在文学问题上展开；这些仍只是小样本观察，不能承诺长期没有口癖。该轮使用最终适配器，不应与前文的候选对照混为同一轮实验。
