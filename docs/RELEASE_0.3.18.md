# 0.3.18：工具调用与对话恢复

本机修复版，2026-10-07。基于这次失败对话、OpenCode 实际调用记录和同环境联网对照修复，审计见 [TOOL_CALLING_AUDIT_2026-10-07.md](TOOL_CALLING_AUDIT_2026-10-07.md)。

## 用户可见行为

- 工具参数保留用户原始姓名字形，日语语音要求不会再把搜索中的「音无彩名」换成「音無彩名」。Windows 字形比较只用于发现对应的原文，发出的名称必须来自用户文本或角色身份，无法唯一对应的名称不猜测替换。搜索自身时使用身份文件里的名称。[Windows 字形映射文档](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-lcmapstringex)
- 人物、角色和作品先按原始名称搜索。`web.search.subject` 指定名称；结果未提到名称时，Bing 受限回退到精确名称查询。RSS 格式异常或无有效结果时尝试普通 HTML，只提取真实搜索结果块，验证页不会被当作搜索成功。
- 相同搜索在当前任务最多请求两次，随后提示读取已有来源或调整策略。不同搜索返回相同 URL 时提供重复结果反馈。字面名称匹配只作为筛选提示，仍需要读取来源核实。
- `web.fetch` 保留正文里的公网链接，返回正文总长度和 `next_offset`，可通过同一 `source_id` 续读完整缓存正文。正文缓存最多 16 页 / 8 Mi 字符；来源过期明确要求重新读取。链接最多返回 100 条，并标记总数及是否截断。
- 同一批独立 `web.search` / `web.fetch` 最多三个并发，结果按原始调用顺序回传。文件写入、共享浏览器页面及桌面操作仍按顺序执行。取消会等待并发子请求停止。
- 一个原生工具调用的参数 JSON 损坏时，给该调用返回 `invalid_arguments`，其他调用仍执行并保留结果。损坏参数不会替换成可执行的空参数；回传仍保留原始调用 ID 和参数文本。
- 任务报告格式或任务语义校验失败时，保留已经提交的语音和工具结果，再请求一次不提供工具的报告修复。修复轮禁止执行 NDJSON 工具或操作；已经说过的话不重复。没有提交过语音时可补首段事实回答。任务类型、已约定完成条件和真实证据校验继续生效，修复失败明确结束任务。
- 取消后给尚未收到回执的原生调用补充「完成状态未知」的失败记录，已完成调用使用真实结果。下一句保持工具调用与回执配对，不自动重放操作。
- 等待界面根据真实回退事件更新进度，并提供「停止」。网络超时和连接失败有明确代码，日志记录调用 ID、异常类型和耗时；任务报告诊断记录校验原因与字段名。
