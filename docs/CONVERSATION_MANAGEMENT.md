# Ayana 话题与上下文管理

日期：2026-10-05。

小窗口名字下方的「正在聊」显示当前话题；点击后查看最近五个话题和当前摘要，点「＋」开始新话题。新话题默认解除仓库与目标窗口，也可以勾选「新话题沿用当前材料」。切换话题会停止旧语音、运行中的任务和未确认的操作，返回后由用户的新消息继续，不自动重放任务。

「全部话题与记录」打开管理窗口的「话题与记录」页。这里可以搜索话题、修改当前名称、查看用户和 Ayana 双方的中文/日语记录、加载更早记录、查看当前摘要和解除仓库/窗口绑定。话题首条消息自动生成初始名称。

## 后端行为

- `conversation_id` 标识用户话题；进程 `session_id`、模型和前台应用变化不创建新话题。仓库选择不会把同一话题拆成多个历史分组。
- 会话名称、当前选中项、仓库路径、模型轮次和摘要保存到本机 SQLite。旧记录一次性迁入「之前的对话」，取最新的旧模型分区作为接续上下文，保留旧的其他分区记录。
- 重启恢复当前话题、摘要和仓库。窗口绑定需要重新观察，不从历史 HWND 恢复控制目标。
- 较早的完整模型轮次接近字符预算时，使用当前配置的模型发起一次独立摘要请求，保留目标、事实、已定结论、工具实际结果和未完成事项。摘要和剩余完整轮次一同落盘；原始双方记录仍可分页查阅。
- 摘要失败或被取消时保留原上下文，不静默删除旧轮次。界面提示正在整理，失败可以重试或开始新话题。当前预算沿用项目的字符估算，不声称是精确 token 容量。
- 迟到的旧播放回执仍写回原话题，不覆盖新话题的回复、表情上下文或任务。离开尚未完成的对话时，将原始问题和中断证据留在原话题，未确认操作不作为已执行结果。
- 关闭历史保存后，话题仅在当前进程内保留，并与已保存话题隔离；重新启用保存不会把临时话题写入历史。

长期个人记忆的自动提取与跨话题检索没有包含在本次功能中。话题摘要只用于本话题接续。

## 验证

`tests/test_conversations.py` 覆盖话题隔离、模型切换、重启、旧记录迁移、分页、临时历史、中断任务、迟到回执、材料恢复、摘要持久化和失败保留。桌面状态测试覆盖切换清理、旧事件拒绝和历史分页。

实际 Electron 验证脚本：

```powershell
node scripts/verify_conversations.mjs --playwright-root '<Playwright 的 node_modules 目录>'
```

脚本在隔离用户目录中运行，使用本地模型接口模拟器和静音模式，验证真实 Electron 与 Python 后端的切换、改名、摘要、最小宽度布局和服务重启，并保存截图及 JSON 报告。可加 `--packaged '<打包输出的 win-unpacked/Ayana.exe>'` 检查打包后的应用与独立 Python。NSIS 便携启动器不支持 Playwright 的调试管道参数，使用现有的 `verify_portable_demo.mjs --exe '<便携 EXE>' --isolated-companion --cleanup-only` 验证实际解包启动和退出。该验证不代表外部模型摘要质量或音色听感评估。

本次源码完整回归为 189 项通过、7 项跳过；最后的 SQLite 派生快照存储调整通过 31 项相关回归。TypeScript、生产构建、桌面状态与播放器测试通过。源码与打包应用的六项真实桌面流程均通过；打包应用的报告位于 `.runtime/benchmarks/conversations/1791184049283/report.json`。

本机独立交付包：`apps/desktop/release/Ayana-0.3.2-context-win-x64.exe`。该包单独命名，避免覆盖同时开发的其他交付包。

本机发现低压缩级别的 7-Zip 24 自动采用 ARM64 过滤器时，旧 NSIS 解压插件无法启动应用；显式使用 BCJ 后便携启动恢复。常规 `package.mjs` 也默认使用 BCJ，保留用户显式设置的过滤器选项。

最终 NSIS EXE 的隔离配置启动、透明小窗口、独立管理窗口和正常退出验证通过，无错误；报告保存为 `.runtime/benchmarks/conversations/1791184049283/portable-launcher-report.json`。
