# 日语快路径与中文字幕对照实验

2026-10-04，在当前开发机上实测 DeepSeek 官方 `deepseek-flash`。保留现有“同流逐句日语→中文”作为默认。本次独立翻译没有展示稳定的首句优势，且中文字幕更晚、请求更多。没有修改运行服务或发布包的翻译行为。

## 方法

比较实施方案第 7.4 节中的 A、B 两条路径：

- A：一次流式请求，按“日语句 1、中文句 1、日语句 2、中文句 2”提交完整 JSON 对象。
- B：主流只生成日语；每个日语对象完全闭合、通过项目语句校验后，立即启动独立翻译请求。主流继续生成下一句，翻译并行运行。

测试三个中文问题：陌生 Python 仓库的阅读顺序、函数输入与返回值、打断后的继续方式。每次要求两句短日语。顺序为 A/B、B/A、A/B，复用同一 HTTP client；没有额外预热请求或失败重试。

根据 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)和[思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，请求使用 SSE 流式输出、`thinking.type=disabled`，每个请求最多 1000 个输出 token。独立翻译请求只接收已提交日语和对应语句键。

时间均在客户端用单调时钟测量：从主请求发起到完整 JSON 对象接收并校验完成。中文字幕时间同样相对主请求起点，因此包含独立翻译的网络等待。没有运行 TTS 或播放，数据不能直接代表用户实际听到声音的时间。

## 实测结果

单位：毫秒，四舍五入。每条路径在每个问题上各跑一次。

| 问题 | 路径 | 第一日语句 | 第二日语句 | 第一中文字幕 | 第一字幕滞后于日语 | 全部完成 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 仓库阅读 | A 同流 | 414 | 577 | 467 | 53 | 618 |
| 仓库阅读 | B 独立 | 542 | 564 | 1049 | 507 | 1418 |
| 函数输入/返回 | A 同流 | 718 | 969 | 794 | 76 | 1054 |
| 函数输入/返回 | B 独立 | 996 | 1125 | 1521 | 524 | 1728 |
| 打断后继续 | A 同流 | 674 | 894 | 768 | 95 | 959 |
| 打断后继续 | B 独立 | 542 | 698 | 1264 | 723 | 1266 |

按相同问题比较 B−A：第一日语句延迟的中位差为 **+127.5 ms**，平均差 **+91.2 ms**；第二日语句的中位差为 **−12.6 ms**；第一中文字幕的中位差为 **+581.5 ms**；全部完成的中位差为 **+674.5 ms**。B 在三个问题中只有一个让第一日语句更早，三个问题的第一中文字幕均更晚。

分别汇总路径的绝对中位数时，B 的第一日语句为 542 ms，A 为 674 ms；这个汇总与逐题配对的结果不同。样本很少、问题和生成句子不同，不能用该绝对中位数宣称独立翻译获得稳定优势。

| 路径 | 总 API 请求数 | 输入 token | 输出 token | 总 token |
| --- | ---: | ---: | ---: | ---: |
| A 同流，三个问题 | 3 | 551 | 329 | 880 |
| B 独立，三个问题 | 9 | 980 | 372 | 1352 |

数量来自 API 的 usage 回执；没有把 token 数换算为金额。两条路径的全部语句和字幕对象均通过协议/关联校验，没有漏句或错配键。未做盲测、语义质量评分或日语自然度评分，协议通过不能证明翻译质量相同。

## 当前选择与复测条件

当前短句教学保留 A。同流中文字幕在本次测量中仅比对应日语迟 53–95 ms；B 增加请求与字幕等待，第一句改善也不稳定。主流程仍然在完整日语对象到达时立即提交 TTS，不等待中文。

若实际长回答出现“中文生成阻塞下一句日语”，或更换模型/网络环境，再扩大样本复测 B，并同时记录真实播放欠载、字幕迟到、句子内容与人工质量评价。本次每路径仅三个样本，不提供 p95 或生产性能承诺。方案中的 C“中文先行再译日语”未在本次实验中执行。

复现：

```powershell
./.venv/Scripts/python.exe scripts/benchmark_translation.py
```

脚本通过现有 Settings 读取本地/DPAPI 凭证，仅接受 `https://api.deepseek.com`。它不修改配置，不输出凭证或请求头。原始语句、时间和 usage 保存至忽略提交的 `.runtime/benchmarks/translation/translation-benchmark.json`。
